audit.service.ts:

методы: logAction(userId, action, details)

сохраняет данные в таблицу audit_logs

формат записи:

{
  "userId": 123,
  "action": "DEAL_CREATED",
  "details": { "dealId": 456 },
  "timestamp": "2025-10-21T12:00:00Z"
}


Подключить AuditInterceptor глобально — логировать все POST, PATCH, DELETE запросы.

Логи сохранять в PostgreSQL + дублировать в Redis (TTL = 7 дней).

2. Rate Limiting

📁 Модуль: src/middleware/rate-limit.middleware.ts

Использовать @nestjs/throttler или кастомное решение с Redis.

Ограничения:

Анонимные: 20 req / мин

Авторизованные: 100 req / мин

Админы: без лимита

При превышении → ошибка 429 Too Many Requests.

3. Error Handling

📁 Модуль: src/common/filters/http-exception.filter.ts

Централизованный фильтр ошибок.

Формат ответа:

{
  "statusCode": 400,
  "message": "Invalid request",
  "timestamp": "2025-10-21T12:05:00Z",
  "path": "/api/v1/deals"
}


Поддержка уровней логирования (warn, error, fatal).

Автоматическая отправка Telegram уведомлений администратору при 500 ошибках (в проде).

4. Database

Добавить таблицу:

CREATE TABLE audit_logs (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id),
  action VARCHAR(100),
  details JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_audit_user_action ON audit_logs(user_id, action);
